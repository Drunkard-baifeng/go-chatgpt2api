# Go 后端

Status: current

本目录提供独立 Go 后端，包含文本与图片协议、异步任务、账号控制面、观测及外部集成。使用 Gin、PostgreSQL、Ent、pgx v5、goose 和 `httpclienttls v1.2.0`；图片放大使用纯 Go `imaging.Lanczos`。不提供 SQLite 驱动、回退或转换，控制台和图片处理均内嵌，运行时无需额外脚本引擎。工具链和固定依赖见 [go.mod](go.mod)，安全补丁来源见 [运行环境](../README.md#运行环境)。

| `/v1/editable-file-tasks`、`/v1/ppt/generations`、`/v1/psd/generations` | 有效身份提交、按归属查询与删除 PPT/PSD 异步任务，两个生成路径均返回任务行 |
| `GET /files/*file_path` | 公开随机产物下载，须存在成功任务元数据；不列目录 |
| `/api/system/update-status`、`/api/system/update-task`、`/api/system/update` | 管理员检查稳定发布、查询跨重启任务及受理在线更新；成功受理返回 202，不支持的部署方式或重复提交返回 409 |

原延期清单中的路由均已移入所属处理器，不再保留统一 501 占位。路由已注册不等于完整协议兼容；下文明确输入子集、关闭的能力和外部验证缺口。未知接口和缺失静态资源返回 404，OpenAI、Messages 与控制台分别保留对应错误形状；页面路径刷新回退至控制台入口。

普通文本流式／非流式及网页静态 4K 生图已有专用账号实测；隔离协议回归不等于全部真实上游能力已验收。证据及尚未验证范围集中见 [构建与验证](#构建与验证)，部署和迁移门槛见 [部署准备](#第-7-阶段验证与部署准备)。

新前端通过显式 HTTP 消费这些领域契约。用户密钥验证直接读取既有 TEXT JSON，停用、轮换与删除即时生效；成功鉴权后记录最近使用时间，具体持久化规则见下文。控制台资源通过 Go embed 编入可执行文件，由同一监听端口提供页面、静态资源与 API。目前只支持单活动进程，文件目录及同库实例不能作为多实例部署使用。

## 账号与控制面

账号操作仅限管理员，普通列表与详情返回状态、标签、能力、诊断及操作事件，不回显 AT/RT。显式凭据读取和导出仍为敏感管理员接口，响应禁止缓存。导入支持 `tokens`、`accounts` 或 `credential_text` 三者之一；例如：

```json
{
  "credential_text": "专用 AT 1----专用 RT 1\n专用 AT 2----专用 RT 2",
  "sync_after_import": false,
  "return_items": true
}
```

`AT----RT` 每行一个，支持多行、空行与 BOM。也支持完整账号对象及已有本地 JSON 的嵌套凭据字段。每批最多 1000 条、请求最多 32 MiB、每个 AT/RT 字段最多 64 KiB；数据库完整保存 TEXT。全批先校验，格式错误按行返回安全诊断且整批不写入。按 AT 去重，保留稳定管理 ID、轮换历史指纹和未知 JSON 字段。导入默认在原子保存后同步；显式 `sync_after_import:false` 只保存。同步失败不回滚已经保存的账号。

管理接口支持分页筛选、选择预览、单项编辑、原子批量启停/分组/删除/计数重置，以及 JSON/TXT/ZIP 导出。带集合 `revision` 的修改执行 CAS，旧修订号返回冲突且不部分写入；未提供时仍通过事务与锁串行保存。账号组沿用独立的 `account_group_configuration`，不新增表或改变领域所有权。

刷新 AT 与同步账号资料/图片额度是两项操作。刷新使用隔离的 OAuth 会话，资料同步只查询已有账号信息，不提交对话或生图。远程维护全局并发由 `account_processing_concurrency` 控制，默认 30、范围 1–100；单账号网络预算 60 秒，已取得的轮换结果及维护诊断分别用独立 5 秒预算保存，批任务最多 2 小时。后台最多 4 个活动任务、64 条任务记录，终态保留 10 分钟，关闭时取消并收口；任务记录在内存中，重启后不恢复。网络失败不判为 RT 永久失效，只有上游明确终止性错误才标记。成功轮换保留管理 ID，并通过旧凭据 CAS 避免覆盖人工修改。

账号池按轮转选择，排除停用、异常凭据和停用账号组。可在 YAML 使用 `upstream.account_id` 固定账号，固定 ID 也不能绕过可用性及模型筛选。生成前必要时恢复 AT，续期后按最新账号状态和重新加载的账号组复查准入；期间被停用的账号或分组不会继续生成，已轮换凭据仍保留。每张图片的每次尝试独立持有 Lease、占用账号和代理容量、更新调用计数并在终态释放；图片失败换号规则见下文。文本及明确固定账号的实际生成不自动换号。账号测试接口复用文本/图片的完整执行、资产及调用记录生命周期，不单独模拟成功。

每张新栅格图片在生成前，通过账号仓储做来源和套餐初筛、预留账号及代理名额、远程核验凭据及额度，再复查最新状态、套餐、来源和账号组。核验与生成沿用同一已选代理出口，本地 `quota=0` 且状态正常也可进入核验。每张新图片最多预检 20 个不同稳定账号，凭据轮换不会重复尝试同一账号；预检落选释放名额，不增加生成尝试、失败、换号及最近使用计数，也不消耗 `image_max_account_attempts`。单个候选的出口、网络或核验失败继续尝试其他候选；只有候选均远程明确额度耗尽才返回 429 `image_quota_exhausted`，混合不可用返回 503。取消及总截止继续生效，存储错误中止；已有外部容量满额的 429 策略不变。SVG 使用文本名额；已有会话只读续查固定原账号，不重新进行生图预检。认证错误目前复用 Go 既有同步恢复及后台生命周期，未提供图片专用异步认证验证队列。

代理出口按账号 → 账号组 → 默认配置解析，引用只有 `direct/group/custom`，未指定才继承。组支持随机、轮转和时间窗口选择；无效或停用引用明确失败。节点图片容量由代理所有者预留并由账号 Lease 释放。同一规范化出口 URL（含认证信息）共享计数，多个启用引用采用最小非零上限，0 不额外限制；组内选取有空位的节点，全组满额明确返回 429。连接探测只访问固定 ChatGPT 目标，最多 4 个同时执行、每次 15 秒，不跟随重定向；clearance 明确不支持。备用出口配置可保存，但当前生成链路不切换备用出口。

代理探测从固定 `https://chatgpt.com/cdn-cgi/trace` 的成功响应中提取校验后的出口 IP 和两位地区代码，结果及节点健康同时投影 `status`、`exit_ip`、`country`、`checked_at`，不回显其他响应内容。响应最多 64 KiB；取消或超时覆盖旧健康状态。最近健康仅在当前进程内有界保存，重启丢失。组测试只探测启用节点，总预算 30 秒，返回逐节点结果及完整的成功／部分成功／失败摘要；已保存节点按组与节点 ID 探测时使用服务端认证，不依赖脱敏 URL。操作说明见[代理管理](../new_frontend/README.md#代理管理)。

设置从统一规范校验，保留未知持久字段，支持修订冲突和显式清空敏感项。全局附加指令已从 Go 设置页、设置投影及写入规范移除，不自动向请求注入 system 消息；旧持久字段不再投影或消费，无需数据迁移。业务运行时消费账号处理并发、单账号图片并发、单次数量上限（1–4）、多图并行、图片流/轮询预算、轮询等待、保留小时数及超分开关；控制台读取自己的请求超时。入口实际安装备份、WebDAV、清理和后台账号维护执行者后，设置才投影对应能力。以下七组基础设置已经接入实际消费者，后续调用或调度轮次读取当前值：

| 设置组 | 生效行为 |
| --- | --- |
| `log_levels` | 筛选进程控制台的 debug/info/warning/error 输出，不过滤调用记录或实时详情 |
| `gif_models` | 同时控制 GIF/SVG 的逐图片模型准入，并更新模型目录能力和修订号 |
| `image_remove_conversation_after_result` | 图片保存且被任务接受后隐藏官网会话；清理失败只保留诊断，不撤销产物成功；SVG 文本会话不执行此清理 |
| `image_settle_enabled`、`image_settle_secs` | 在只读轮询中等待图片引用稳定并再次确认，再解析和下载结果；不重复提交生成 |
| `refresh_account_interval_minute` | 启动即扫描待核验图片登录态、临期 AT 和限流账号，之后按当前间隔调度；与手动维护共用容量并避开正在生图或维护的账号 |
| `base_url` | 设置图片公开地址；未配置 YAML 公共地址时参与生成、图库、缩略图、日志和自动推送地址解析 |
| `image_account_retry_enabled`、`image_max_account_attempts` | 控制每张图片失败后尝试不同账号及次数，继续受失败分类、固定账号、检查点和整批截止约束 |

备用出口切换仍未接入。后台账号远程维护与按策略自动移除账号是不同生命周期。启动配置仍只读 YAML，不能从设置页覆盖数据库或管理员密钥。

普通用户密钥以 SHA-256 保存，随机生成的新密钥只在创建响应出现一次。管理员密钥和记录不可通过普通密钥管理接口覆盖；停用、轮换和删除不依赖缓存，下一请求即生效。

数据库密钥成功鉴权后，以 UTC 更新 `last_used_at`；列表和管理更新响应优先显示当前进程较新的使用时间。同一密钥首次使用立即尝试持久化，后续鉴权每 60 秒最多尝试一次，写入与管理修改共用集合修订行锁，保留未知 JSON 字段，并防止旧凭据在轮换、停用或删除后写回。时间写入失败不影响已经确认有效的鉴权，进程仍保留最新时间；未落库的时间在重启后不会保留。无效或停用密钥、YAML 配置管理员密钥不会更新数据库密钥的时间。历史未采集的使用时间不补造。

## 文本接口

文本请求示例：

```json
{
  "model": "auto",
  "messages": [{"role": "user", "content": "你好"}],
  "stream": true
}
```

文本请求上限 1 MiB，`messages` 为 1–128 条；未提供消息时可用 `prompt`。忽略未消费的额外 SDK 字段，未消费的采样参数不会限制网页上游。文本消息中的图片引用经过同一有界读取、校验和上游上传链路；图片模型或 `modalities:["image"]` 请求分流到图片执行者，搜索工具复用搜索执行者。

文本规则见 [文本请求与目录](internal/chat/request.go)，模型透传和思考归一化由该模块统一处理。目录推荐 `auto`（默认）和 `gpt-5.6`；执行也允许其他有效模型名，最多 255 字节且不含换行或 NUL。模型原名传给上游，不改写为其他模型，也不因 `auto` 带思考而拒绝。

思考参数按字段是否存在依次选择 `thinking_effort`、`reasoning_effort`、`reasoning.effort`，高优先级的空值不会回退。`low/medium/high` 保留；`xhigh/extended` 归一化为 `extended`；空字符串、`null`、`none`、未知值（含 `standard`）和非字符串均不传。账号是否可调用及最终解析模型由上游决定。

当前目录 `schema_version:1`，包含 2 个推荐文本模型和 7 个网页图片模型，默认图片模型为 `gpt-image-2`，`image_max_n:4`。放大能力随运行时开关投影；`capabilities.gif_models` 是 GIF/SVG 共用的当前模型列表，空列表关闭两种格式。目录修订号随能力变化更新。

SSE 只输出面向用户的 assistant 正文，过滤历史回显、思考及工具消息；保留稳定补全 ID 和正常终止帧。异常、截断或空正文不会伪装成成功。流开始前按 HTTP 错误返回，开始后以流内错误和 `[DONE]` 结束；客户端已断开时无法保证错误帧可达。`usage` 使用本地词表和图片尺寸估算，不代表上游计费记录。

每次调用先保存初始记录，再准备上游协议，最终交付后保存终态。记录包含身份、账号管理 ID、选中账号邮箱、公开/请求上游/解析模型、思考档位、会话及安全失败码，输入文字保留原文及换行，最多 50000 字符，超限明确标记截断；失败正文只保存下文规定的有界脱敏诊断，不保存完整上游响应、原始图片、AT/RT 或代理密码。网络响应与数据库提交无法原子化：响应已交付后若终态写入失败，只记录安全日志，记录可能残留 `running`；进程强杀也可能残留，本阶段尚无自动恢复。

## 文本预算与准入

文本执行者统一持有从初始记录到上游准备、读取和最终交付的总截止，`upstream.text_timeout_seconds` 默认 300 秒，可配置范围 1–86400 秒；应用入口为文本配置 32 个活动槽位，饱和返回 HTTP 429，不排队、自动换号或重放。输入读取预算为 30 秒；默认响应头和上游读取空闲预算各 30 秒，下游每次写入最多 30 秒且不超过剩余总预算，取消会主动中断写入。终态记录另有 5 秒清理预算，失败流帧另有 2 秒预算，二者不延长正常生成预算。

Sentinel 依次执行 prepare、PoW、受限 Turnstile 与 finalize，再提交一次会话。PoW 最多 500000 次尝试；挑战虚拟机不执行浏览器 JavaScript，最多 20000 步、深度 32、2 秒及 8 MiB 浅分配，JSON 展开另限 20000 节点和 1 MiB 最坏转义字节。超限或未知挑战明确失败。

## 同步图片接口

生成请求示例：

```json
{"model":"gpt-image-2","prompt":"画一只猫","n":1,"response_format":"url","output_format":"png","size":"1024x1024","quality":"high"}
```

默认 `n=1`、`response_format=b64_json`、`quality=auto`。返回 `created` 秒时间戳和 `data` 数组，数组元素含 `url` 或对应的 `b64_json` 字段。`n>1` 时每张图片分别选号、预留并发名额并创建独立会话，`image_parallel_generation` 默认 `true`，关闭后逐张串行但仍分别选号。上游多候选逐个检查，取该张首个通过完整图片校验的有效产物，不用候选数量代替公开 `n`。同步多图保留部分成功结果：普通上游失败不撤销其他成功图片，返回成功项；取消、整批截止、存储或检查点失败等整批错误仍终止交付并回收未被任务接受的资产。

`image_account_retry_enabled` 默认开启，`image_max_account_attempts` 默认 4，包含第一次使用的账号，按每张图片分别计数。错误允许换号时排除该图已经尝试过的账号，池中没有其他账号或达到次数上限后返回最后一次失败。是否换号依据文本／失败分类，不只看错误是否可重试；HTTP 400、审核拒绝、输入错误、文本结果和取消不换号。明确上游失败及轮询预算用尽可以按策略换号，先清除旧恢复检查点再创建新尝试；无法确认提交是否受理、检查点或资产保存失败时不自动重放。异步任务仍可对保留的已知会话只读续查。固定 YAML 账号或管理员测试指定的账号不换号。一次尝试中的生成 POST 仍只提交一次。

网页图片模型映射：`gpt-image-2` 对应上游 `gpt-5-3`；`gpt-image-2.5`、`gpt-image-2.5-flare`、`gpt-image-2.5-sunburst`、`gpt-image-2.6`、`gpt-image-2.6-flare`、`gpt-image-2.6-sunburst` 对应 `auto`，均使用 `picture_v2`。这不是最终底层生图工具模型的保证。图片不另造思考模型或参数；上游按相同网页协议决定执行过程。`size` 和 `quality` 作为原文提示，不施加尺寸格式或质量枚举；`quality:"max"`、`"hd"` 和 `size:"3840x2160"` 均可传入。省略质量默认 `auto`，帧字段按是否提供保留 `null`、布尔值和原始文本。未消费的标准扩展字段会忽略。

普通网页图片模型不限制账号来源。`codex-gpt-image-2` 要求 Codex 来源且套餐为 Plus、Team、Pro；`plus-codex-gpt-image-2`、`team-codex-gpt-image-2`、`pro-codex-gpt-image-2` 进一步限定单一套餐。来源别名 `cpa/cpa_json/remote_cpa/sub2api` 统一为 Codex；套餐忽略大小写、空格、下划线和短横线，Business 归入 Team，ProLite 不归入 Pro。`/api/model-catalog` 与 `/v1/models` 根据本地可用账号快照列出 Codex 及对应套餐模型，读取目录不联网核验，无可用账号时保留原网页模型回退。

Codex 模型通过同一 TLS 会话直接提交 `/backend-api/codex/responses`，使用 `gpt-5.5` 和 `gpt-image-2` 图片工具；参考图内联为 data URL，传递原始提示词、尺寸、质量及输出格式，不进行网页 Sentinel 或文件上传。支持 JSON/SSE 内联结果，取首张通过完整校验的图片，之后的真实错误不撤销已有有效结果；成功后附带的 401 仍向凭据生命周期反馈。结果沿用公开图片响应、格式转换、超分、存储和逐图计数。响应受会话总预算、单图 50 MiB、事件数、节点数及深度限制；未确认终态的断流不重放，没有网页会话续查能力。以上为隔离协议验证，尚未进行本轮真实 Codex 出图验收。

图片超分由 `image_upscale_enabled` 控制，默认关闭。开启后，`size` 匹配 2–5 位宽高及 `x`（忽略大小写与两侧空白）、每边不超过 8192 且总计不超过 4000 万像素时，任一实际边不足便精确拉伸到目标宽高；两边均已达到目标则跳过放大。发布前统一执行一次处理：解码、纠正方向、按需通过纯 Go `imaging.Lanczos` 放大，最后一次编码为请求格式，不再先转码后重新解码放大。同格式且无需放大或方向修正时直接保留原始字节；未指定格式时沿用原始编码尺寸判断是否需要放大，指定格式时按纠正方向后的尺寸判断。处理耗时合并为实际的一段“处理图片”，跳过处理时不记录转码或超分阶段。放大能力编入后端二进制，部署时无需额外图片处理程序，控制台仅保留放大开关。已有 `image_upscale_engine` 设置不再参与执行或设置投影，原有持久数据保持兼容，无需迁移。处理取消不发布结果；放大或其编码失败时回退到未放大的图片，仍保证请求格式与方向，只有回退也无法满足时才返回错误。

`output_format` 支持 `gif/png/jpeg/webp/svg`，`jpg` 归一化为 `jpeg`，忽略大小写和首尾空白；省略、`null` 或空字符串保留上游原始编码。静态栅格格式在发布前按 EXIF 方向纠正旋转、镜像后转换真实图片字节；`response_format` 独立选择 URL 或 base64。JSON 生成、JSON/multipart 编辑、异步任务和 Responses 图片工具共用格式规则，下载扩展名及响应类型跟随最终编码。透明图转 JPEG 使用白底，JPEG 编码质量为 95；WebP 使用内嵌 libwebp WASM，质量 95、方法 4，保持 `CGO_ENABLED=0` 构建，资源来源与许可见 [编码资源说明](internal/images/codec/README.md)。不保证与其他编码器的压缩率或字节完全一致。转码共用图库解码锁，限制单图 4000 万像素、转换结果 50 MiB，以及整批结果 100 MiB；WebP 编码器线性内存另限 512 MiB，原始解码图像及输出字节不计入此上限，编码期间可由上下文取消。取消或超限不发布资产。

GIF/SVG 共用 `gif_models` 模型开关，均不支持 `stream:true`；SVG 仅用于没有参考图或遮罩的生成。GIF 将帧参数加入提示，保留上游实际字节、帧时长、循环及处置方式，不将返回的静态图片伪装为动画。GIF 完整解码前限制最多 1024 帧及累计 4000 万帧像素。SVG 通过 `auto` 文本会话生成，从回复正文提取完整安全 SVG，拒绝仅有下载链接的响应；静态 XML 白名单禁止脚本、事件属性、动画、外部资源、嵌入位图、DTD、实体声明和非 XML 声明的处理指令。文档最多 4 MiB、128 层、100000 个节点，每边最多 8192、总面积最多 6400 万像素。GIF/SVG 均跳过超分，SVG 原字节用于 URL/base64、资产和矢量缩略图。

编辑接口支持 JSON 的 `image/images/image_url`，值可以是公网 URL、base64、data URL，或含 `url/image_url/b64_json/base64` 的对象及数组；JSON 遮罩字段为 `mask`。multipart 同时支持文件和文本引用，参考图字段接受 `image/image[]/images/images[]/image_url/image_url[]`，遮罩接受 `mask/mask[]`。遮罩按透明度或灰度规则合成，尺寸不同时以 Lanczos 调整，多个参考图复用最后一个遮罩。最多 16 张参考图、16 个遮罩，单图 50 MiB、两组共享 100 MiB，请求整体上限 140 MiB；接受可完整解码的 PNG、JPEG、WebP 和有界 GIF，不接受 SVG 参考图，每图最多 4000 万像素。公开成功结果沿用生成接口的 `created/data/usage` 和 URL/base64 投影，图片流使用 `image_edit.completed`，不伪造部分图片事件或追加 `[DONE]`；用户参考图不会作为生成结果返回。

网页参考图先完成文件登记、无账号认证的签名 PUT 和上传确认，再准备首页、Sentinel、conduit 并提交一次图片会话。文件及附件按顺序命名为 `image_1.png`、`image_2.png`，MIME、大小及宽高来自实际输入；会话按参考图顺序提交 `image_asset_pointer`，提示词位于最后。签名上传使用网页协议的 Blob、Origin、Referer、浏览器 User-Agent、Accept 和语言请求头，不转发账号 Authorization、Cookie 或 Sentinel。PUT 总预算及响应头预算为 120 秒，外站 GET 总预算及响应头预算为 60 秒，均受父调用剩余总截止约束。直连在 TCP/TLS 建立前可尝试其他已验证公网地址，发送 HTTP 后不自动重放 PUT；代理隧道继续固定已验证 IP。

签名上传失败通过统一分类投影公开错误，返回 `error.message/type/param/code`，其中 `param` 为 `null`；签名资源的 401/403 不等于调用者密钥失效，也不标记上游账号凭据无效。响应读取失败即使已收到 200/201，也返回传输错误而非成功状态。诊断保留失败阶段、实际 HTTP 状态和最多 64 KiB 的错误正文输入，再经统一脱敏及 4000 字符摘录供日志和监控使用；不记录签名 URL 或凭据。旧记录没有采集的原因不能补造。上传顺序、请求/返回形状、慢上传、取消及失败诊断已有受控协议回归，本轮未进行真实上游参考图编辑验收。

Codex 仍使用上文的内联参考图协议；Go 按实际检测的 MIME 构造 data URL。JPEG/WebP 参考图保留实际类型，不统一标记为 PNG。公开请求和结果形状共用图片协议，不保证跨语言的图片编码或完整上游报文字节相同。

应用入口为图片配置 32 个活动批次槽位，在读取大请求前准入；每账号图片并发由设置限制为 1–3，代理节点另有限制。全局批次满或本批没有活动尝试可等待且账号容量满时返回 HTTP 429；同批多图因自己的其他图片占位时，只在总截止内等待本批释放名额，因此单账号并发 1 也能逐张完成多图。整批从读取输入到最终交付共用 `image_stream_seconds + image_poll_seconds + 30` 秒，默认 `80+60+30=170` 秒；每次尝试的 SSE 和只读轮询各有独立窗口，选号、换号和等待均不延长整批截止。输入读取和每次下游写入最多 30 秒，最终记录另有 5 秒清理预算。流断开或 SSE 窗口到期且已知会话时，仅查询已有会话并解析结果；每次提交是否已被受理不确定时不会自动重放。轮询预算用尽明确失败。

网页图片 SSE 支持 `delta_encoding` 的 `"v1"` 前导标记，忽略非对象元数据；`append` 支持合并消息的 `metadata` 对象。省略 `o` 的 `/message/metadata` 及子字段更新按替换处理，普通 `image_gen_inline_upsell` 提示不会中断图片流；真实错误、输出补丁操作及累计状态大小继续校验。图片结果若指向当前固定上游站点或站内相对路径，复用该账号的 TLS 会话、鉴权和 Cookie 下载；其他站点继续使用无账号身份的隔离传输。站内下载不跟随重定向，不向外站发送账号凭据。

网页图片的流式回复与只读续查均识别面向用户的 `commentary` 终态文字，识别成功终态名称及 `metadata.status` 回退。确认终态文字后不再等待 HTTP 关闭或反复空轮询；没有图片产物时返回 HTTP 400、`upstream_text_reply` 和上游可读原文，并由既有调用记录及实时监控保留原因。工具参数、`analysis` 和显式 `end_turn=false` 的进度不会据此结束生成，已有图片引用继续解析。轮询阶段预算用尽返回 `image_poll_timeout`，不将该阶段的 context 截止误报为整批超时或提交结果不确定；父调用取消及总截止仍保留。轮询失败诊断附带当前轮最近 8 条消息的有限字段快照，每条文字最多 500 字符，再经统一脱敏和总长度限制；不保存完整会话或用户消息。

图片资产仍由 [图片存储服务](internal/images/assets.go) 唯一写入本地文件，不放入 PostgreSQL，使用独立数据目录。`images.directory` 默认 `data/images`，相对路径以 YAML 所在目录为基准。发布前校验数据，通过临时文件、同步和原子重命名发布到日期及随机 ID 路径。公开图片地址统一按 YAML `images.public_base_url` → 业务设置 `base_url` → 当前 HTTP 请求协议和 Host 解析，支持路径前缀；不会使用任意转发头。地址须为无账号信息、查询参数及片段的有效 HTTP(S) URL。生成、图库、缩略图、日志补全和自动推送消费同一解析入口；经 HTTPS 反向代理部署时应显式配置公共地址。无配置及 HTTP 来源的内部任务保留相对地址。资产地址公开，只有持有随机地址者可读取，无目录枚举。本地索引、缩略图和显式清理由同一服务维护，具体边界见下文。

同步静态图片成功返回 `created/data/usage`；每张包含 `revised_prompt`、`width/height` 及 `b64_json` 或 `url`。`response_format` 仅 `b64_json` 返回 base64，其他值返回 URL。用量按内置词表及图片 patch 规则本地估算，URL 输出使用请求尺寸估算。支持 `stream:true` 的 `image_generation.completed` 或 `image_edit.completed` SSE（包含 base64 和单张 usage），不伪造 partial，不发送 `[DONE]`；URL 流没有 completed 图片项。当前在整批生成完成后交付事件。生成 JSON 的字段类型/必填错误返回 422 和字段校验错误体。

公开续接任意已有会话仍未迁移，不能据此认为已覆盖所有上游生图能力。调用记录保存真实接口、尝试数、实际换号数、最终图片数及安全元信息，保存有界输入文字及公开产物完整地址，不保存原图、上游签名 URL 或凭据；多图正常分别选号不计为失败换号，批次账号和会话字段投影最后更新的一次尝试，详情按图片和尝试分别展示。客户端写入失败会清理本批资产，已交付成功响应后的数据库终态写入失败会保留资产并记录诊断。

## 异步图片任务

[图片任务服务](internal/imagetasks/service.go) 拥有任务准入、归属、幂等、调度和文件持久化；执行继续复用同步图片的账号 Lease、调用记录、输入与资产生命周期。提交端点保留图片参数子集及可选 `client_task_id`，支持共享输出格式规则，返回任务行，结果固定为 URL；公开同步接口的 `mask`、帧字段和流式模式尚未迁移至任务持久化，任务端点仍拒绝这些字段，不会静默丢弃。任务入口未提供来源且未配置公共地址时资产 URL 为相对路径。同一身份与客户端 ID 重复提交返回原任务；不同身份互不读取任务，管理员也不越过归属。客户端断连不会取消已经持久受理的工作。

启动配置 `image_tasks.directory` 默认 `data/image_tasks`、`workers` 默认 4（1–32）、`queue` 默认 32（1–256）。任务目录与图片目录不能相同、嵌套或指向同一可解析目录；均须使用本服务独立数据目录。提交在读取请求体前预留有界名额，饱和返回 503 `image_task_queue_full`。原图片执行容量与账号、代理限制仍独立生效。输入读取最多 30 秒、140 MiB；执行预算与同步图片一致，不因排队延长执行期。

`tasks.json` 最多 10000 条、32 MiB，只保存安全请求参数（含输出格式）、资产引用、归属和每张图片的私有账号／会话恢复证据，不保存提示词或凭据。输出格式在重启续查时保留，旧任务缺失该字段时继续使用原始编码；旧单槽恢复文件仍可读取。活动输入（提示词及编辑参考图）临时保存在私有 `spool/`，终态、关闭及重启时清理。目录由操作系统文件锁独占，不能由两个活动服务共写。索引损坏拒绝启动，持久化失败停止正常准入和列表，避免继续输出未落盘的状态。

公开状态沿用 `queued/running/success/partial_success/failed/text_review`，后端返回终态、数量、阶段及 `actions.resume_poll`；新前端据此显示续查操作，部分成功也可续查。已持久接受的图片在后续失败时保留；未被任务接受的本批新资产回收。任务成功持久化交付后，调用记录或账号终态保存失败不会撤销已交付结果。

重启将遗留排队/执行任务标为 `task_interrupted`，保留已完成图片，不重放输入。存在安全会话证据时可调用续查，`extra_timeout_secs` 默认 30、范围 5–120 秒，另有执行准备预算。续查分别固定各未完成图片原账号，只读取各自已知会话，不上传、不提交生成，也不补发尚未提交的剩余图片；数量不足时保留部分结果并明确失败。下调新的 `image_max_n` 不阻止旧任务只读续查。

任务保留期使用 `image_retention_hours`（默认 24），列表和提交时按需清理终态记录，活动任务不清理；任务过期不删除图片。关闭先停止准入、取消工作并最多等待 10 秒；若工作者尚未退出，入口继续等待其实际结束后才释放任务锁、资产、账号和数据库，不能保证不遵守取消的执行者在固定时间内退出。

## 本地图库

图库通过管理员 `/api/images` 系列接口提供搜索、标签、日期筛选、分页、原图下载、批量 ZIP、删除、存储统计、过期清理和磁盘目标清理（含 dry-run）。栅格公开缩略图最长边 512，格式为 JPEG，GIF 使用首帧；缩略图按资产代次缓存。SVG 每次读取先验证安全文档并返回原矢量，不转为 JPEG。批量删除最多 1000 个路径；ZIP 最多 100 张、原图总计 100 MiB。按筛选全选删除最多 1000 张，查询与删除不是同一快照；新前端当前使用显式路径删除。

图片存储服务独占 `.gallery/catalog.json`、标签、缩略图及删除墓碑。索引上限 100000 条、32 MiB，原子保存；损坏或未知结构拒绝启动，不静默清空。启动有界协调已存在的合法随机路径图片、缺失文件及孤立缓存。删除先持久化墓碑，再移除原图与缩略图，最后按操作 ID 和资产代次收口，重启可以继续协调中断删除。

存储服务支持 `local/webdav/both`。WebDAV-only 上传成功后不保留本地原图；原图、缩略图、ZIP 和备份通过同一资产入口读取受管远端副本，并验证字节与摘要。远端元数据、删除墓碑、资产代次和 GenBox receipt 随图库索引持久化；网络操作不持有图库总锁。同步、压缩与删除仍经过同一所有者，不另建索引。压缩后原图及缩略图 URL 携带代次以更新缓存，旧随机路径仍可读取当前资产。

GenBox 先验证接入，再上传 multipart 并校验 receipt；成功不删除源图。启用自动推送后，仅完整成功交付的 Studio 图片任务入队，包含成功续查；同步图片接口、部分成功和失败交付不自动推送。自动队列为 2 个工作者、32 个等待项，按资产代次去重；满额不阻塞生成，不提供持久重放保证。手动推送可用于检查失败并重试。

保留期后台清理与管理员显式清理均由清理服务编排，任务记录过期仍不代删资产。同步请求在发布后进程被强杀时，尚无跨请求事务恢复日志，可能留下资产，由图库查询和清理处理。

## 兼容协议与可编辑文件

Responses 支持无服务端会话存储的文本输入、instructions、历史文本、思考档位和 SSE；`web_search` 或 `image_generation` 工具分别复用搜索及图片执行者，图片输入复用现有参考图校验。图片 tool_choice 可触发默认图片工具。Messages 支持 system、文本历史、图片、工具声明、关联的 tool_use/tool_result 以及 Anthropic SSE 事件；工具输出解析当前支持 XML `tool_calls/tool_call` 形式。三个入口均忽略未消费字段，`max_tokens`、采样及并行工具选项不会约束网页上游输出。本地 usage 估算不代表计费统计。Responses SSE 使用 data 帧与 `[DONE]` 结束；不支持服务端会话存储。

搜索固定使用 `gpt-5-5`，执行 Sentinel 准备、单次提交及已知会话只读轮询。三种文本入口共用文本总预算（默认 300 秒），同一 Call Record 与账号 Lease；不建立另一套账号池。协议解析额外最多允许 2 个同时读取的请求体，饱和时在读取前返回 429，读取限时 30 秒；Responses 上限 140 MiB，其余文本协议为 1 MiB。该门限仅保护输入解析，不替代执行者容量。

可编辑文件由 `editablefiles` 独立持有 PostgreSQL 元数据及 `editable_files.directory` 产物目录，图片目录、图片任务目录和文件目录禁止相同或嵌套。默认 2 个工作者、16 个等待项（最大 8/64）；先预留容量，再读取输入。账号选择复用既有 Lease 并要求付费套餐，上游固定 `gpt-5-5-thinking` 和 `extended`，总预算 1200 秒，参考图最多 4 张、单张 10 MiB、总计 30 MiB。已提交的生成不重放，只读取已知会话；主文件和素材 ZIP 通过格式与压缩边界校验后一起发布。

每个产物最多 50 MiB，ZIP 最多 2048 项、解压总计 250 MiB。PPTX 校验演示文稿及关系，PSD 校验真实头和像素结构，不能用 HTML 改扩展名通过。`client_task_id` 在归属身份内幂等；活动任务删除返回 409，队列满返回 429。重启中断活动任务并清理已知未交付文件，不重放生成。公开下载只允许随机受管路径且要求成功任务元数据，数据库不可用时下载也不可用；这与图片独立资产读取的边界不同。

## 观测、提示词与远程导入

日志列表、详情、删除与概览共用 Call Record 仓储；执行、密钥、状态、结果说明、HTTP、错误码、图片和分辨率分别展示，列宽按比例分配，窄桌面在表格内滚动，手机使用卡片。详情保留输入原文和可复制的完整结果地址，旧记录的相对图片路径按配置的公开地址或当前服务地址补齐，未采集的历史原文无法补回。后端统一投影业务阶段及各次步骤的实际起止时间，默认时间线合并阶段起止并隐藏 HTTP/SSE 内部回调；同一图片、同次尝试的成功查询与等待各汇总为一条，保留次数和有效耗时，失败与换号独立保留。汇总不显示伪造的连续起止区间；旧事件不完整但同次尝试的累计指标仍完整时采用累计耗时，并注明历史缺失。耗时总览使用请求生命周期的墙钟分段，步骤按实际开始时间排列，嵌套步骤选择一层，多图并发不可相加；只有累计数据的旧记录单独展示且不虚构时间。PPT/PSD 按文件业务统计，不计作图片数量。实时窗口从既有调用生命周期订阅开始、进度和终态；最多跟踪 1024 个活动请求，超限仅影响观测，不另占调用执行容量。窗口重启清空，持久日志继续可查。概览使用现有指标表与可用账号投影，停用或异常的无限额账号不表示账号池健康。

新请求的日志与实时详情共用结构化诊断：请求尺寸、质量、返回及输出格式、请求张数、参考图数量、实际出图分辨率、脱敏出口、上游响应码和请求 ID。图片按每张图、每次尝试保留账号、失败原因、换号关系及耗时；文本、搜索和文件生成也接入相同诊断快照。阶段覆盖账号选择、上游准备、参考图上传、SSE、图片轮询、解析、下载、格式转换、超分、保存与响应交付。总览使用调用生命周期的墙钟时间，细分阶段单独展示，避免将并发图片和嵌套 HTTP/SSE 耗时重复相加。

HTTP 诊断记录实际观测到的 DNS、TCP、等待、首包及完整响应耗时；SSE 记录首事件、事件数、最大及收尾空窗。当前固定 TLS 库未暴露独立握手计时，连接复用也可能没有 DNS/TCP 回调，原始诊断明确记录未采集，默认业务时间线不展示这些底层回调。耗时分析用于定位主要阶段，不能直接判定代理或上游故障根因。HTTP/SSE 汇总指标取观测到的最大值，各次事件保留对应耗时。

实时监控按实时概览、入口与出口、账号与切换、上游准备、生成与传输、结果与交付输出六组共 48 项指标。后端从最近 200 条完成调用的同一诊断快照计算统计，活动请求只贡献当前并发与阶段分布；部分成功计入成功，文本回复不计失败且不进入成功率分母，限流独立计数并进入分母。P95 使用有效正耗时样本和最近秩法，缺失或不适用的耗时显示“—”；慢请求为总耗时至少 120 秒，列表包含活动请求及完成窗口内的慢请求。换号恢复率按切号后成功请求数计算，包含部分成功。

执行容量来自文本池、图片池与文件工作者，分别限流；图片异步任务复用图片池，不再次叠加工作者数量。Go 入口和出口满载直接拒绝，不伪造入口、首包或出口排队耗时。出口租约耗时由实际预留入口采集，活跃出口复用真实图片租约计数，同一出口去重，包含直连。本地拒绝/繁忙合并窗口内的无号、并发拒绝，以及同一窗口期间最近最多 200 次文本/图片入口满载事件；入口拒绝不创建数据库调用记录，也不进入完成数或成功率。会话流耗时保留并发墙钟，断流计数仅统计流读取中断（包括读取期间超时），不包含业务拒绝、无效消息或主动取消；多流断流耗时取最慢的一条，不相加，亚毫秒中断仍计一次断流但没有有效 P95 耗时样本。

图片失败同时保留公开 API 状态码、上游 HTTP 状态、`upstream_error`、`upstream_text` 和 `raw_error`：HTTP/SSE 错误、上游任务失败、纯文字拒绝及协议解析失败均有对应诊断入口。每段原文最多保存 4000 字符，保留换行并脱敏凭据、Cookie、代理口令和签名地址；公开失败说明、调用记录、实时详情及逐图尝试共用同一来源。详情区分上游 HTTP 200 与业务失败，历史未采集的正文明确显示缺失，不补造原文。

这些字段扩展既有 `call_records.payload`，不需要新增表或迁移。输入文字与失败摘录有界脱敏后保存；不保存原始请求 JSON、完整上游响应、原图、AT/RT、代理密码或签名下载地址。每次调用最多保留 32 次账号尝试及 128 条诊断事件；成功轮询先按阶段汇总，窗口满时优先淘汰成功 HTTP/SSE 回调，避免其挤掉业务步骤，超过上限的完整历史仍不保留。实时窗口详情另外保留请求开始事件；重启丢失不影响已持久化的终态诊断。

日志与监控的隔离回归覆盖多图尝试、输入原文、结果地址补全、轮询汇总及手机至 4K 的详情布局；验证边界见 [构建与验证](#构建与验证)。

运行环境由观测服务按需采集，共享一秒缓存，不写入数据库。运行时版本通过 `runtime_label` 和 `go_version` 返回。Windows/Linux 采集当前进程 CPU、常驻内存、系统可用内存口径的使用率、`images.directory` 所在磁盘使用率、系统发行版和内核版本。进程 CPU 按可见 CPU 容量归一化到 0–100%；容器识别及 cgroup v1/v2 内存限制、CPU 配额以进程可见资源为准。网络速率统计当前可见的已启用非回环网卡，不表示单个 Go 进程的网络流量。CPU 与网络首次只有基线，间隔至少一秒的后续采样才返回速率；网卡变化或计数器重置会重新建立网络基线。无法采集的单项返回 null，前端显示 `--`，有效空闲速率返回 0。

提示词服务使用 Go 内嵌的独立默认快照及既有领域表；读取和启动不联网。管理员手动刷新有总预算和容量限制，完整校验清单与数据后保存；更新失败保留上次可读快照。来源启停仅改变所属领域设置，不修改内嵌文件。

CPA/sub2api 连接、来源列表和导入进度由 `remoteimports` 持有，实际账号写入仍走 Account Repository 和既有维护容量。管理员显式配置的回环/私网服务可以连接；每次拨号固定经过校验的 DNS 结果，拒绝链路本地、元数据和其他无效地址，不读取环境代理、不跟随重定向。任务接受后脱离 HTTP 生命周期，重启标记中断而不重放。OAuth 会话最多保留 10 分钟，使用 state、PKCE 和一次消费；完成操作要求完整回调 URL，不能只粘贴 code。

## 备份、清理与升级

备份支持 R2 SigV4、受管前缀内列表与删除、定时调度、轮换及可选 OpenSSL 兼容加密。PostgreSQL 由独立 `pg_dump` 进程读取，要求客户端 17+ 且不低于服务端主版本；Dockerfile 安装 18 客户端。整个归档上限 512 MiB、100000 个文件，包含数据库及选定的三个文件领域快照。各所有者快照分别稳定，**不是跨数据库与文件的同一时点快照**；生产切换恢复必须先停止全部写入者，同时备份数据库和图片、任务、文件目录，并在独立副本验证恢复。本阶段没有生产恢复或切换演练。

清理服务启动后每 30 分钟检查保留期和账号自动移除策略，也提供管理员 dry-run 与显式执行；活动或维护中的账号不删除。日志清理后重建所需指标，域内失败如实反馈，不把部分清理伪装为全局成功。定期清理不执行远程账号检查。

## 在线更新

`internal/updates` 从固定公开仓库 GitHub Releases 查询稳定版；成功结果缓存 10 分钟，检查失败缓存 1 分钟，手动检查跳过缓存。只接受匹配 Windows/Linux amd64、arm64 的正式附件，校验 SHA256SUMS、发布平台提供的摘要、程序构建平台及版本；网络、权限或校验失败不会停止现用服务。开发构建显示开发状态，不查询正式版；容器和已识别的 systemd 托管实例可检查版本，使用部署工具升级。

直接运行的正式下载包可以从控制台确认安装。独立助手在旧进程完成 HTTP 排空、任务关闭并真正退出后替换程序，沿用原配置绝对路径和工作目录重新启动；新进程通过自身 HTTP 就绪检查后才报告成功。新版本启动失败会恢复旧程序并尝试重启。请求受理后短暂断连会继续轮询；受理响应丢失时重新查询实际任务，不将历史成功当成本次更新结果。

程序所在目录须可写且有下载、暂存和保留旧程序的空间。任务、日志和恢复文件保存在可执行文件旁的 `.<程序文件名>.update/job-<任务ID>/`，仅替换当前程序，不覆盖配置、许可或业务文件。助手交接后持续等待旧进程退出；长请求可能延迟安装。更新任务按操作系统文件锁串行执行，异常重启遗留的任务明确标记中断。

持续无法重连时，先确认旧、新服务及安装助手的进程状态，检查任务目录中的 `install.log`、`service.log` 和外层 `task.json`。需要手动恢复时先停止确认属于本次更新的服务及助手，将任务目录里的 `previous.exe`（Linux 为 `previous`）复制回原程序路径，再用原 `serve --config` 命令启动；保留更新目录用于排查。恢复程序不等于数据库降级，涉及不兼容结构变更时按备份恢复流程处理。

本次重新发布的 `v0.1.0` 已包含在线更新，可安装后续更高的稳定版。此前下载的旧 `v0.1.0` 包没有更新器，须手动替换一次；相同版本号不会触发在线更新。Docker 使用 `docker compose pull api` 与 `docker compose up -d api`，不从控制台替换容器内文件。当前已验证 Windows 真实进程的更新成功、校验失败、启动失败恢复、安装前失败恢复及慢退出监督，另有四平台交叉编译；Linux/ARM64 真实运行和容器升级仍需对应部署验收。备用出口切换及其他扩展能力仍受各自执行边界限制。

## 本地启动

首次从项目根目录执行 `npm --prefix new_frontend ci --registry=https://registry.npmjs.org` 和 `node scripts/build.mjs --prepare`，准备内嵌资源。以下命令在后端目录执行。安装 [运行环境](../README.md#运行环境) 指定的 Go，或允许 Go 自动下载 [go.mod](go.mod) 要求的工具链。

```powershell
if (!(Test-Path ./config.yaml)) { Copy-Item ./config.example.yaml ./config.yaml }
```

仅首次创建配置，已有文件保留。编辑 `config.yaml`，填写 `auth.admin_key`、PostgreSQL 地址、数据库名、角色和密码。示例管理员密钥为空，未填写会拒绝启动。角色和 PostgreSQL 服务应事先存在；使用独立的 Go 数据库，不与其他活动服务共用数据库及文件目录。

```powershell
go run ./cmd/chatgpt2api serve --config ./config.yaml
```

启动时自动检测并初始化空数据库，已有当前结构幂等复用，通过校验后才开始监听；无需先手动执行数据库命令。默认监听 `127.0.0.1:8100`，直接打开即可登录控制台，API 使用同一端口。配置路径必须显式提供，相对路径以调用者工作目录为基准。示例和可选字段定义分别见 [配置示例](config.example.yaml) 与 [配置实现](internal/config/config.go)。

若启动提示“图片目录已被占用或无法加锁”，先检查是否还有旧后端进程，再检查图片目录权限。停止旧进程后由操作系统释放锁，不要删除 `writer.lock`、索引或图片来绕过独占保护。

前端使用同源反向代理或 Vite 代理时，保留 `server.allowed_origins: []`。通过 `VITE_API_URL` 直连独立端口时，在 YAML 中明确填写前端来源，例如 `allowed_origins: ["http://localhost:5173"]`，以浏览器实际地址为准；不接受通配符、路径或尾斜杠。预检允许授权头，实际响应允许读取请求 ID 和导出元信息；未授权来源不获得跨域响应头。此策略不替代 Bearer 鉴权，也不使用跨域 Cookie。

配置只读取单个严格 YAML 文档，拒绝重复键、未知字段、错误类型和空管理员密钥。`DATABASE_URL` 等环境变量不覆盖应用配置；为避免 pgx 的 libpq 默认链，存在 `PG*` 环境变量时会拒绝建立数据库连接。用户目录中的密码文件和数据库客户端证书也不作为隐式配置。`verify-ca`、`verify-full` 使用系统信任的 CA。

可信代理默认为空，不信任外部转发头。应用记录请求 ID、路由模板、状态和耗时，不记录凭据、请求体、查询参数或异常内容。退出时先排空 HTTP 请求，超过关闭预算后取消活动请求，再停止图片任务；工作者实际结束后关闭图片、账号及数据库资源。

| --- | --- |
| `db status` | 只读检查，输出 `empty`、`legacy` 或 `ready` 与版本，不创建数据库或台账 |
| `db verify` | 只读验证已登记的受支持结构，不匹配时非零退出 |
| `db migrate` | 允许创建确认不存在的数据库，显式初始化空库；已迁移时幂等 |
| `db adopt --offline` | 仅为完整匹配的既有 PostgreSQL 结构登记版本台账，不执行建表基线或改写业务记录 |
| `serve` | 自动检测数据库，创建确认不存在的数据库并复用 goose 初始化空库；已登记的当前结构幂等复用，校验成功后监听 |

创建目标库需要访问维护库及 `CREATEDB` 权限；已有数据库不会被删除、替换或重新指定所有者。普通启动与 `db migrate` 使用同一内嵌 SQL 版本迁移和 PostgreSQL 会话锁，初始化或校验失败时拒绝启动。无台账的既有结构仍需显式离线接管，未知或更高版本结构不会自动修改。Ent 和 pgx 共用同一个有界连接池，不调用 Ent 自动迁移。

基线覆盖现有 17 张领域表。结构验证包含列、类型、空值、默认值、主外键、索引、触发器、视图、行策略及序列定义；接管还检查必要修订行、TEXT JSON 对象和自增 ID 序列位置。保留完整长 AT、摘要唯一索引、RT 和未知 JSON 字段。未知结构、字段漂移或更高版本均拒绝，不自动修复或降级。

接管前停止全部写入者，在已批准的独立副本上验证并保留可用快照，再执行：

```powershell
go run ./cmd/chatgpt2api db status --config ./config.yaml
go run ./cmd/chatgpt2api db adopt --offline --config ./config.yaml
go run ./cmd/chatgpt2api db verify --config ./config.yaml
```

`--offline` 是操作人员的明确确认，程序无法证明其他写入者已停止。未经隔离迁移验证，不要连接既有生产数据库。迁移使用 PostgreSQL 会话锁，接管在同一事务中锁表并登记；等待锁和执行均受操作预算限制。未实现自动破坏性回退，生产切换与恢复仍需独立演练和授权。

## TLS 会话

[上游会话](internal/upstream/session.go) 为每个账号和代理组合分别持有连接及 Cookie。生成会话公开构造入口仅面向固定的 `https://chatgpt.com`；RT 刷新另建仅面向 `https://auth.openai.com/oauth/token` 的隔离会话，不携带 ChatGPT AT 或 Cookie。生成会话只接收站点内路径，不跟随重定向或自动重放 POST，不启用 HTTP/3 竞速。调用方在所有路径关闭响应体。

底层会话默认总预算 170 秒，文本和图片执行者分别传入其总预算；默认响应头 30 秒、读取空闲 30 秒、响应 16 MiB，调用上下文可更早取消。单个 SSE 行或事件上限 1 MiB，文本正文上限 4 MiB，图片当前消息累计状态上限 1 MiB。TLS profile 与浏览器头由同一库生成。默认请求语言：首页 `Accept-Language` 为 `zh-CN,zh;q=0.9,en;q=0.8`，会话默认值为 `zh-CN,zh;q=0.9,en;q=0.8,en-US;q=0.7`，已有账号协议头 `OAI-Language` 为 `zh-CN`；不修改提示词来指定语言，上游原文仍原样返回，不保证每次均为中文。受控本地测试已覆盖直连、CONNECT 和 SOCKS5H 的真实 TLS/HTTP2、ClientHello 特征与浏览器头一致性、证书拒绝、读取空闲与总截止、取消、Cookie 隔离、字节限制，以及已受理 POST 断连后不重放。账号协议会话的 HTTPS 代理受信成功路径尚未验证；普通文本及静态图片的真实验证见 [构建与验证](#构建与验证)，当前思考透传仍缺少新的真实上游证据。

参考图和签名图片字节由 [资产传输模块](internal/assettransfer/transfer.go) 使用标准 HTTP 客户端单独传输，不携带账号认证或 Cookie。现有指纹库没有约束实际拨号 IP 的策略接口，因此外部图片传输将每一跳 DNS 结果全部校验为公网，再把选定 IP 固定到实际直连、CONNECT 或 SOCKS 目标，保留原 Host 和 TLS SNI。最多 3 次重定向，不允许 HTTPS 降级；上传不跟随重定向，也不自动重试。PUT 总预算及响应头预算为 120 秒，GET 为 60 秒，均服从整批截止，单图最多 50 MiB，不接收 HTML。沿用所选账号的显式代理，不读取环境代理；配置代理时只接受 HTTPS 图片目标，HTTP 图片地址明确失败。受信代理路径、TLS/SNI、重定向拒绝和取消已有隔离测试；外部资产的 HTTPS/SOCKS 代理成功路径及真实 CDN 尚未实测。

本地 TLS 联调可在项目根目录创建被忽略的 `go.work` 并加入本地模块。正式构建使用固定发布依赖和 `GOWORK=off`，不依赖本机 TLS 源码路径。

## 图片耗时与超时排查

日志中的“解析结果”（`resolve_ms`）表示向上游请求图片下载链接，不是本地 JSON 解析。网页链路会请求 `/backend-api/files/{id}/download` 或 `/backend-api/conversation/{conversation}/attachment/{id}/download`，取得链接后才下载图片、处理和保存；卡在此阶段时尚未进入超分。

账号协议请求受单次响应头、读取空闲、轮询阶段及整批总截止分别约束；默认单次响应头和读取空闲均为 30 秒。轮询窗口结束后，若已发现图片引用且整批仍有剩余时间，会再解析已有候选，因此可能看到多次等待响应，以及轮询窗口结束后的额外解析；所有步骤仍受整批总截止约束。外站图片字节传输使用上一节的独立预算，不能与站内链接解析混为一谈。

排查时先区分公开 API 状态、每次上游 HTTP 结果及最终业务状态。此前某次上游返回 200，只能证明那次请求成功收到响应，不能证明后续链接解析或出图成功。结合各次诊断中的发送完成、首字节和超时位置判断主要耗时；缺少 DNS/TCP/TLS 回调或未收到响应时，不能据此断言是代理或上游的具体故障。历史未采集的信息不补造；反向代理与客户端预算也须覆盖请求耗时，可参考 [Nginx 示例](../deploy/nginx-server.conf.example)。

## 部署准备

正式程序内嵌完整控制台。部署可使用可执行文件或 [Compose 示例](../docker-compose.yml)，无需单独静态站点；可选 HTTPS 入口见 [Nginx 全站反代](../deploy/nginx-server.conf.example)。镜像构建上下文为项目根目录，前端与 Go 分阶段编译，运行镜像只保留程序、数据库客户端和许可文件。容器运行尚需在具备 Docker 的环境验收。
