# Go 部署与切换

Status: current

本手册用于独立部署、隔离演练及切换评审。当前能力和验证证据由 [后端说明](../../go_backend/README.md) 维护；数据恢复格式和命令见 [备份与恢复](backup-and-restore.md)。本手册不是生产切换批准，也不表示 Python 的业务数据已能完整迁移。

## 运行时安全基线

核查日期：2026-11-13。本节维护本项目的运行时版本、官方安全来源和升级步骤。

| 运行时 | 固定版本 | 使用位置 | 官方安全来源 |
| --- | --- | --- | --- |
| Go | 1.27.4 | 后端工具链、CI、Docker 构建阶段 | [Go 官方发布记录](https://go.dev/doc/devel/release#go1.27.4)，2026-11-10 发布 |
| Node.js | 22.23.5 LTS | 独立 Vue 控制台的依赖安装和构建 | [Node.js 22.23.5 安全发布说明](https://nodejs.org/en/blog/release/v22.23.5)，2026-11-11 发布 |

Go 此补丁包含 cgo、Go 命令、编译器、链接器和 `net/http` 安全修复，并包含此前补丁的修复；Node.js 此补丁包含 HTTP/2、TLS 和代理错误信息泄露等修复。版本是核查日的安全基线，不保证此后没有新漏洞；第三方模块、npm 依赖和容器系统软件包仍需分别维护。

[go.mod](../../go_backend/go.mod) 声明最低 Go 工具链为 1.27.4；允许自动工具链时会下载所需版本，使用本地工具链时旧版会被拒绝。CI 从 `go.mod` 安装，Docker 构建阶段固定 `golang:1.27.4-alpine`。需要精确复现时设置 `GOTOOLCHAIN=go1.27.4`，再执行下文的校验与构建命令；仅安装新版 Go 不会修补已有二进制，必须重新构建并替换、重启服务。可用 `go version` 核对工具链，用 `go version -m <二进制路径>` 核对产物的编译版本。

控制台 [`.node-version`](../../new_frontend/.node-version) 固定默认 Node 版本，`package.json` 的 `engines.node` 允许 `>=22.23.5 <23`，项目 `.npmrc` 启用 `engine-strict`，安装时拒绝旧补丁及未经验证的其他主版本。CI 使用此版本文件。先通过自己的 Node 版本管理器安装并切换，再执行 `node --version`、`npm ci` 和构建；版本文件不会自动更新本机工具或旧开发进程，切换后需重启开发服务。Go 后端运行环境不需要安装 Node.js 或 Python。

## 独立构建与交付边界

构建输入仅需本仓库，不需要 Python 源码、另一套前端、原工作区的 `node_modules`、`go.work` 或本地 TLS 库。固定依赖为发布的 `httpclienttls v1.2.0`；使用对应锁文件，不能在发布时临时改成本地路径。

使用上述安全基线中的 Go 工具链，从后端目录执行：

```sh
GOWORK=off go mod download
GOWORK=off go mod verify
CGO_ENABLED=0 GOWORK=off go build -mod=readonly -buildvcs=false -trimpath -ldflags='-s -w' -o ./bin/chatgpt2api ./cmd/chatgpt2api
```

从前端目录执行：

```sh
npm ci --registry=https://registry.npmjs.org
npm run build
```

运行目录单独放置二进制、选定 YAML 和三个文件目录；前端只部署 `dist/`。不要把源码目录作为站点根目录，不把 YAML、数据库密码、`.env`、备份、日志或本地数据加入构建产物。后端的 `.dockerignore` 仅允许 `go.mod`、`go.sum`、`cmd/`、`internal/`、`ent/` 和 Docker 构建文件，并排除测试与环境文件；SQL 和内置 JSON 属于必要的嵌入资源。

图片尺寸放大统一使用编入后端的纯 Go `imaging.Lanczos`，后端运行环境无需安装 Node.js、npm、Sharp 或额外放大脚本。前端的 npm 命令仅用于独立控制台的安装与构建。

两次构建摘要一致只证明固定输入下的构建结果一致。正式交付还须记录源码提交、工具链、模块校验结果、平台及产物摘要；当前工作区尚未提交，不把本机验证产物当作已发布版本。

## PostgreSQL 与启动配置

从 [配置模板](../../go_backend/config.example.yaml) 准备目标 YAML。填写管理员密钥、数据库角色和密码；账户必须能够连接 PostgreSQL 后才谈得上创建数据库。认证失败不会通过重新建库解决，不重置现用角色或密码。

优先由管理员预建目标库并授予应用权限。需要由程序创建不存在的目标库时，该角色须有维护库连接和 `CREATEDB` 权限。`serve` 能创建确认不存在的数据库，但不会建表；新建空库须执行 `db migrate`。已有 Python 数据库副本须按离线接管路径处理，不能执行空库基线。

启动前，确认配置中的数据库、三个文件目录和外部集成都只指向选定环境。恢复副本也会带入备份、自动推送和清理设置；隔离测试应使用假凭据或专用资源，不能让副本访问现用 R2、WebDAV、GenBox 或其他集成。所有目录相对 YAML 所在目录解析。

当前只支持单活动进程。目录锁只保护同一组可解析文件目录，不能阻止不同目录下的两个进程共同写一个数据库；PostgreSQL 的迁移锁也不是应用运行互斥锁。部署系统负责停止旧写入者和防止多副本启动。

启动提示“图片目录已被占用或无法加锁”时，先核对旧后端进程和监听端口，停止确认属于该服务的旧实例后重试；没有旧实例时再检查 `images.directory` 及其 `.gallery` 目录的读写权限。锁由操作系统持有，进程退出后释放，磁盘上的 `writer.lock` 文件继续保留；不要删除锁文件、图库索引或图片，也不要通过关闭独占保护启动第二个写入者。

## 容器部署准备

现有 [Compose 示例](../../docker-compose.yml) 管理 API 和 PostgreSQL，前端由宿主静态服务器托管。修改示例前先确认卷名、角色和 YAML；不要对已有 PostgreSQL 卷通过改 `.env` 来假设密码会同步改变。

在仓库根目录准备 `.env` 与 `go_backend/config.yaml`。容器 YAML 使用 `server.host: 0.0.0.0`、`database.host: postgres`；数据库名、角色和密码与初始化配置一致。YAML 作为只读文件挂载，运行用户 `10001:10001` 必须可读。

新建空库部署顺序：

```sh
docker compose up -d postgres
docker compose run --rm api db migrate --config /app/config.yaml
docker compose run --rm api db verify --config /app/config.yaml
docker compose up -d api
curl --fail http://127.0.0.1:8100/health/ready
```

恢复已有归档时改用恢复手册流程，不先运行 `db migrate`。恢复到卷的文件和目录须授予 `10001:10001`，否则归档中的 `0600` 文件可能仅能被解压操作者读取。不要执行 `docker compose down -v` 来处理升级或连接错误。

示例的容器停止等待为 20 秒，不能理解为全部任务必在 20 秒完成。HTTP 排空、备份终态保存和任务退出各有预算；长任务可继续等待实际收口。正式环境按观察到的停止耗时配置更宽的 `stop_grace_period`，并演练强杀恢复；强杀可能留下中断任务或未结束的调用记录，不自动重放已受理生成请求。

## 反向代理与前端

[Nginx 站点示例](../../deploy/nginx-server.conf.example) 默认监听回环 `8080`，静态目录指向独立的前端 `dist`，后端指向回环 `8100`。正式接入时把其中的 `root` 与 `location` 合入现有 HTTPS 站点，并保留正确的证书及 HTTP 跳转配置。先运行 `nginx -t`，验证通过再按运维流程加载。

API、健康检查、图片、缩略图和文件路径全部转发至 Go，未知 API 应仍返回 JSON/404，不能落入前端 SPA。前端路由回退到 `index.html`；不存在的 `/assets/` 文件直接 404。

示例关闭响应缓冲、请求缓冲、缓存和失败自动换上游，允许 SSE 及时交付，并避免代理重放已受理的 POST。上传整体限制为 `140m`，与后端图片编辑预算匹配。代理读写空闲预算示例为 660 秒；它是相邻读写之间的空闲预算，不能当成请求总时限。文本默认总预算、搜索和图片限制仍由后端执行者决定；如果调高应用预算，也必须重新核对 Nginx、CDN、客户端与控制台超时。仅调代理超时不会增加上游生成预算。

日志中“解析结果”及多层超时的含义见 [图片耗时与超时排查](../../go_backend/README.md#图片耗时与超时排查)。先按实际请求阶段判断耗时，再核对对应预算；不能把此前一次上游 HTTP 200 当作最终图片成功。

## Python 数据接管门槛

数据库结构兼容与业务数据兼容必须分别验证。`db adopt --offline` 只登记受支持的数据库结构台账，`db verify` 通过不代表图库、任务或产物已经可读。

目前已发现以下实际格式差异，不能通过直接复制目录解决：

| Python 数据 | Go 当前要求 | 切换前必须完成的工作 |
| --- | --- | --- |
| 可编辑文件使用 `asset-<带连字符 UUID>`，产物 URL 与目录对应旧格式 | `asset-<32 位十六进制>`；数据库读取、启动恢复和公开下载共用该校验 | 明确转换或兼容策略，同时验证全部任务状态、存储 ID、结果 URL、产物与归属；目前含旧格式记录的库可能启动失败，成功记录也可能无法查询或备份 |
| 图库使用 `YYYY/MM/DD/<时间>_<摘要>`，标签/索引位于旧 JSON | 随机日期路径和 `.gallery/catalog.json` | 在图片所有者边界内迁移路径、标签、索引和资产引用；保留旧公开 URL 的策略须先明确 |
| `image_tasks.json` 中 `tasks` 是列表 | Go `tasks.json` 使用版本号和任务映射，含归属与恢复证据 | 显式转换任务字段、归属、状态和结果引用；活动输入与已提交生成不得直接重放 |

在这些业务格式迁移有独立副本验证前，禁止把“17 表接管通过”表述为完整 Python → Go 切换通过。当前没有自动转换上述旧文件数据的生产命令；不要改正则、批量改库或移动文件来临时绕过检查。

## 隔离切换与回退演练

使用专用数据库和文件副本执行以下顺序，生产操作须另有明确授权：

1. 核对目标能力与数据清单，分别列数据库、图片、图库索引、图片任务、PPT/PSD 及外部存储。先完成所需格式迁移验证。
2. 停止入口写入、后台任务和维护脚本，等待完成或明确中断；确认没有 Python/Go 或其他写入者。保留旧程序、配置和切换前快照。
3. 按恢复手册的 [Go 停机快照](backup-and-restore.md#go-停机快照) 导出静止数据集，再恢复到新空库和新目录。核对文件清单、权限和数据库结构；该路径面向 Go 自有数据，受支持 Python 副本还须完成独立业务格式迁移后才能接管。
4. 启动前逐行对账 17 表的 ID、完整 JSON、集合修订、计数和序列位置，并核对资产摘要及任务引用。不能只比表数量或行数。
5. 保持原写入者停止，启动一个目标实例，检查健康、管理员/用户鉴权、账号、图库及任务归属、原图/缩略图和文件下载；显式执行少量目标写入并确认源库不变。
6. 重启目标，检查新增数据、历史任务和下载仍可用；验证同目录第二实例被拒绝。入口切换后继续只保留一个活动写入者，不使用双实例轮询作为灰度方案。
7. 未接收新写入前可在停止目标后恢复旧入口；接收新写入后，先停写并对账新增内容，再选择经验证的兼容回退或恢复流程。不能直接启用旧快照并宣称无损。

本机 Windows 演练的强制终止验证了重启恢复，并未证明 Linux `SIGTERM` 与容器优雅停止链路。真实上游及外部集成、Linux/容器运行、生产代理、完整 Python 文件迁移和用户验收仍各需对应证据；缺少其中必需项时保持切换准备状态。
